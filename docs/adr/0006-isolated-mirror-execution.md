# 在隔离镜像副本中执行历史改写

所有 BFG 改写和验证都在独立的 Git mirror 副本中进行，用户提供的工作仓库只读检查、不直接改写。skill 可以生成后续推送命令，但不会自动 force-push 或 --mirror 推送。

## 考虑过的方案

- 直接改写用户当前工作仓库：命令路径短，但容易破坏唯一副本和未提交工作。
- 只生成命令，让用户自行准备副本：更保守，但无法保证执行和验证使用的是同一上下文。
- skill 自动建立隔离 mirror 并在其中执行：可恢复性和验证闭环更强。

## 后果

- skill 需要明确镜像副本的位置、来源和保留策略。
- 执行结果必须包含原仓库、镜像副本和验证对象的关联信息。
- 用户需要自行审阅并执行最终推送，以及通知下游 clone 重新同步。
