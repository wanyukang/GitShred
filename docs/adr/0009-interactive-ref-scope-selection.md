# 通过交互式范围选择决定处理哪些 refs

这个 skill 不把 refs 范围固定死为全量或单分支，而是在执行前让用户明确选择。若用户清楚哪些分支或 tag 受影响，skill 只处理用户指定的范围；若用户不清楚，或明确要求做全量检查，就使用 all refs。

## 考虑过的方案

- 始终全量处理：最稳妥，但对明确知道范围的用户来说过于笨重。
- 始终只处理默认分支：最省事，但会漏掉旧 branch 和 tag 中的泄露凭据。
- 交互式选择范围：能适应事故处置和局部修复两种工作方式。

## 后果

- skill 必须把可选范围说清楚，而不能默认猜测。
- 用户指定的小范围处理结束后，报告里要明确说明未覆盖的 refs 仍可能残留风险。
- 用户选择全量检查时，skill 应把 branches、tags 和其他可见 refs 一并纳入审计和清洗计划。
