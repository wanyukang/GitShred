# 先清洁当前版本，再改写旧历史

如果确认清洗规则仍存在于默认分支 HEAD 或当前待发布代码中，skill 必须停止 BFG 执行，先要求用户在正常工作区删除或替换凭据并形成干净提交。第一版不默认使用强制改写最新内容的方式。

## 考虑过的方案

- 直接让 BFG 强制覆盖最新内容：步骤短，但会把源码修复和历史改写混在一起，容易破坏当前版本。
- 先要求当前版本清洁，再清理旧历史：需要额外一步，但边界清晰，也符合 BFG 保护当前版本的安全模型。

## 后果

- 执行前必须检查默认分支 HEAD 和待发布代码是否仍含确认清洗规则。
- “当前版本清洁”和“历史清洗完成”是两个独立状态。
- 用户若不能先修当前版本，skill 只能停在审计和方案阶段。
