# 默认只读并设置历史改写执行闸门

Git 历史修复会改变提交对象、破坏现有引用，并可能影响所有下游 clone；因此 skill 采用“默认只读、明确确认后才改写”的执行边界。它可以在本地副本中执行已确认的清洗和验证，但不会自动 force-push，也不会代替密钥吊销或轮换。

## 考虑过的方案

- 自动完成本地改写并推送：操作顺滑，但误判的破坏面过大。
- 只生成命令、不执行：风险较低，但无法完成验证闭环，也削弱 agent 的价值。
- 默认只读，确认后执行本地改写：在可用性与可恢复性之间取得平衡。

## 后果

- skill 必须区分审计、方案、执行和验证阶段。
- 任何会改写历史的步骤都必须有明确的用户确认。
- 密钥轮换、吊销和下游同步只能作为后续处置建议或独立集成，不能被“清理 Git 历史”隐式替代。
