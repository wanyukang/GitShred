# 只覆盖敏感信息处置，不覆盖仓库瘦身

这个 skill 的第一版只处理 Git 历史中的敏感信息处置场景，不处理超大文件、构建产物、仓库体积优化或 LFS 迁移。BFG 仍可作为执行后端使用，但 skill 的目标不是“让仓库变小”，而是围绕已提交秘密、凭据或私密数据进行风险处置。

## 考虑过的方案

- 同时覆盖仓库瘦身和敏感信息处置：入口更宽，但两类问题的风险模型不同，容易把低风险维护和高风险事故混在一起。
- 只覆盖敏感信息处置：范围更窄，但流程、提示和安全边界可以更强。

## 后果

- skill 不应响应普通大文件清理、packfile 优化或 LFS 迁移诉求。
- 审计与验证要围绕敏感信息是否仍存在，而不是仓库体积是否下降。
- BFG 不能成为 skill 的中心概念；它只是可能用于敏感文本清理的执行后端之一。
