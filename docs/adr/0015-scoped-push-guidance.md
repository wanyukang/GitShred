# 根据 refs 范围生成精确推送建议

这个 skill 不自动推送远端，也不把 git push --mirror 作为默认命令。用户指定局部 branches 或 tags 时，处置摘要应生成尽量精确的 force-with-lease 推送建议；用户选择 all refs 时，先展示影响清单，再把 mirror push 作为需要人工审阅的显式选项。

## 考虑过的方案

- 自动执行 mirror push：闭环快，但可能删除或覆盖远端 refs，且影响范围难以逆转。
- 始终只给通用命令：安全但无法反映用户选择的范围。
- 根据范围生成精确建议并等待人工执行：兼顾可操作性和可审阅性。

## 后果

- 处置摘要必须列出待推送 refs、未覆盖 refs 和潜在下游影响。
- 局部范围与全量范围必须生成不同的命令建议。
- 下游 clone 的重新同步不由 push 命令隐式解决，必须单独提示。
