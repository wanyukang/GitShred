# 第一版采用 SKILL.md 加本地辅助脚本

第一版不做成纯提示词 skill，而是由 SKILL.md 定义交互流程、安全边界和停止条件，并配套少量无外部依赖的本地脚本执行机械步骤。脚本只依赖 Git、shell 和用户环境中已有的 BFG，不自动下载执行器或安装包管理器依赖。

## 考虑过的方案

- 纯 SKILL.md：最轻量，但每次都需要 agent 临场拼命令，误操作和漂移风险较高。
- SKILL.md 加本地脚本：保留交互判断，同时让 preflight、mirror 准备、BFG 调用、prune 和验证变得可重复。
- 引入完整工具链或包依赖：工程化更强，但第一版的安装和供应链边界过重。

## 后果

- SKILL.md 必须定义何时调用脚本、何时停止、何时要求用户确认。
- 脚本输出应尽量机器可读，方便 agent 生成处置摘要。
- 脚本不得绕过执行闸门，不得自动安装 BFG，也不得自动推送远端。
