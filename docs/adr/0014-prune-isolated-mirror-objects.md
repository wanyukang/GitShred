# 在隔离 mirror 中执行对象回收

BFG 改写后，第一版会在隔离 mirror 中执行 reflog 清理和普通 prune，再重新扫描目标 refs 与对象库。原始工作仓库、远端、fork、CI 缓存和其他 clone 不执行对象回收；aggressive GC 需要额外明确确认。

## 考虑过的方案

- 只检查 branches 和 tags：无法确认旧内容没有残留在 reflog 或不可达对象中。
- 对原始仓库执行 prune：风险过大，可能破坏唯一备份或用户仍需的恢复点。
- 在隔离 mirror 中执行普通对象回收：能完成本地验证闭环，同时保持原始仓库可恢复。

## 后果

- “refs 已清洗”和“隔离 mirror 对象已回收”必须作为两个验证状态展示。
- 处置摘要必须提醒远端和其他副本仍可能保留旧对象。
- 不得把本地对象回收描述成远端或所有 clone 的物理清除。
