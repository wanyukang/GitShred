# 第一版只支持 BFG 执行后端

这个 skill 的第一版只支持 BFG 作为历史改写执行后端。BFG 不是 skill 的中心概念；skill 的中心仍是泄露凭据处置，但所有实际清洗命令必须落在 BFG 的可靠能力范围内。

## 考虑过的方案

- 同时支持 BFG 和 git-filter-repo：覆盖面更宽，但后端选择会引入更多判断分支和误操作风险。
- 只生成建议，不执行任何后端：风险更低，但无法完成本地清洗和验证闭环。
- 第一版只支持 BFG：能力边界更窄，但行为更可预测，适合先把泄露凭据处置流程做稳。

## 后果

- 超出 BFG 能力边界的场景必须停止执行，不能自动切换到其他历史改写工具。
- skill 应明确说明“不适合 BFG-only 执行路径”的原因和升级建议。
- 后续如要加入 git-filter-repo，必须作为新的执行后端单独建模和验证。
