# 追踪凭据轮换状态但不执行轮换

这个 skill 不直接吊销或轮换泄露凭据，但必须追踪轮换状态，并在输出中区分“Git 历史已清洗”和“凭据风险已闭环”。如果用户没有确认泄露凭据已经吊销、轮换或失效，skill 不能宣称事故处置完成。

## 考虑过的方案

- 只处理 Git 历史，不关心凭据状态：实现简单，但会制造错误安全感。
- 直接集成外部平台执行轮换：闭环更强，但需要额外权限模型和平台集成，超出第一版边界。
- 追踪轮换状态但不执行轮换：保留安全提醒和事故状态，同时避免越权操作。

## 后果

- 最终报告必须分别展示历史清洗状态和轮换状态。
- 未确认轮换时，输出应标记为“凭据风险未闭环”。
- 未来如要自动轮换，需要为每个平台单独设计权限、审计和回滚边界。
