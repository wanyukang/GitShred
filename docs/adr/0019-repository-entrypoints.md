# 支持本地路径和远端 URL 作为仓库入口

GitShred 第一版支持本地仓库路径和远端 URL 两种入口，并统一转换为隔离 mirror 后再执行审计、BFG 改写、对象回收和验证。远端认证依赖用户已有的 Git 配置和 credential helper，skill 不管理平台登录、访问令牌或 SSH key。

## 考虑过的方案

- 只支持本地仓库：实现简单，但泄露事故中用户常常只有远端 URL。
- 内置 GitHub/GitLab 等平台登录：体验完整，但引入凭据管理和平台权限边界。
- 支持本地路径和远端 URL，沿用 Git 环境：覆盖常见入口，同时避免把 GitShred 变成平台认证工具。

## 后果

- GitShred 不应把 token 或密码拼进命令行，也不应写入处置摘要。
- 远端访问失败时，应停在预检阶段并提示用户修复 Git 凭据配置。
- 已有 bare mirror 可以按本地路径处理，但需要确认它不是唯一备份。
